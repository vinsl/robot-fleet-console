# ADR 0049 — TOTP enrolment QR code: drawn offline with `qrcode`, as React SVG

- Status: accepted
- Date: 2026-11-03
- Requirements: FR-AUTH-3, SEC-WEB-1
- Threats: T21 (XSS on the console), T42 (TOTP secret sent to a third party)
- Implemented in PR-5 (console shell): `apps/console/src/components/TotpQrCode.tsx`

## Context

At the first login the operator enrols a TOTP device (ADR 0044). The console shows the `otpauth://totp` URI as a QR
code and as text. The URI contains the TOTP secret, so whatever draws the code sees the secret. The console runs under
a strict CSP with no `unsafe-inline` and no third-party origin (ADR 0046), so the drawing must not need inline
markup or a network call.

## Decision

- The `qrcode` library (MIT, pinned in the lockfile) computes only the module matrix of the code, at error correction
  level M.
- `TotpQrCode` turns the dark modules into one SVG `path` made of React elements. No markup string is built and
  nothing is set through `innerHTML` or `dangerouslySetInnerHTML`.
- Drawing runs in the browser. No request leaves the page with the secret.
- If the library cannot encode the text, the component renders nothing, and the secret is still shown as text, so the
  enrolment is never blocked by the drawing.

## Alternatives considered

| Option                                                  | Pros                       | Cons                                                              | Why not                                                    |
| ------------------------------------------------------- | -------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------- |
| `qrcode.toString("svg")` with `dangerouslySetInnerHTML` | Smallest code              | Markup string injected into the page                              | Puts an injection path in the console; no `innerHTML` rule |
| A wrapper package (for example `qrcode.react`)          | No drawing code of our own | One more dependency to maintain and audit for a 30-line component | Saves little real work                                     |
| QR image generated by the API                           | Browser code stays minimal | The secret crosses the API and could reach logs or a cache        | Adds a server path that holds the secret                   |
| Public QR service                                       | No dependency              | Sends the TOTP secret to a third party                            | Breaks the secret boundary (T42)                           |

## Consequences

- We own about 30 lines of drawing code. It is covered by the sign-in page test that enrols with a QR code and the
  secret as text (`apps/console/test/pages/sign-in.test.tsx`).
- The console needs no network access to enrol a device, and no third-party origin is added to the CSP.
- A future change to the library version goes through the lockfile and the `make check` gate like any dependency.
