# Threat model (STRIDE)

Living document. Updated by every `security-reviewer` pass. Each threat has a control, a test or
evidence, and a status (`planned`, `implemented`, `verified`, `accepted`).

## Assets

| Id  | Asset                                             | Why it matters                                                 |
| --- | ------------------------------------------------- | -------------------------------------------------------------- |
| A1  | Physical robot behaviour (motion, e-stop)         | Safety of people and goods in a real warehouse                 |
| A2  | Robot identities (X.509 certs, private keys)      | Whoever holds a key can impersonate a robot                    |
| A3  | Operator identities and sessions (Cognito tokens) | Whoever holds a token can command robots                       |
| A4  | Live video                                        | Shows the warehouse and people: confidential and personal data |
| A5  | Audit log                                         | Accountability; must not be altered by users                   |
| A6  | Site maps                                         | Layout of a customer site: confidential                        |
| A7  | AWS account and CI                                | Full control of everything above, and the bill                 |

## Trust boundaries

B1 Internet ↔ CloudFront / API Gateway (HTTP, WebSocket) · B2 Robot ↔ IoT Core (MQTT mTLS) ·
B3 Robot ↔ IoT credentials provider ↔ KVS · B4 Browser ↔ Cognito / identity pool ↔ KVS ·
B5 Lambda ↔ DynamoDB / S3 / IoT data plane · B6 GitHub Actions ↔ AWS (OIDC) ·
B7 Developer workstation (Codespaces, Kali VM) ↔ AWS · B8 Browser ↔ DXF file from the internet.
