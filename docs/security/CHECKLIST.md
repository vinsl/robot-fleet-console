# Security checklist

Tick with the evidence (test name, file, screenshot). Reviewed by `security-reviewer` at the end of
M4, M6, M9 and M10. Based on OWASP ASVS 4.0.3 level 2 (subset relevant to this app), OWASP API Security
Top 10 (2023) and CIS AWS Foundations.

## OWASP API Security Top 10 (2023)

- [ ] API1 Broken object level authorization: every `robotId`/`siteId` checked against the caller's site
- [ ] API2 Broken authentication: Cognito JWT verified by API GW and re-verified claims in Lambda; WS token single use, 60 s
- [ ] API3 Broken object property level authorization: zod `.strict()` schemas, explicit response DTOs
- [ ] API4 Unrestricted resource consumption: throttling, body size, pagination limits, upload limits, rate limit on commands
- [ ] API5 Broken function level authorization: role matrix tested per route (Admin/Operator/Viewer)
- [ ] API6 Unrestricted access to sensitive business flows: e-stop/commands audited and rate limited; demo mode Admin only
- [ ] API7 SSRF: no server-side fetch of user-supplied URLs (DXF parsed in browser)
- [ ] API8 Security misconfiguration: headers policy, CORS allow-list, no default stage logs with bodies, Checkov clean
- [ ] API9 Improper inventory: OpenAPI generated and committed; single stage; no unused routes
- [ ] API10 Unsafe consumption of APIs: robot messages validated as untrusted input

## ASVS L2 (selected)

- [ ] V1 Architecture: threat model maintained; trust boundaries documented; components least privilege
- [ ] V2 Authentication: MFA for privileged roles; no default accounts; initial admin created by script with forced password change
- [ ] V3 Session management: short access tokens, refresh rotation, sign-out revokes refresh token, idle timeout on teleop
- [ ] V4 Access control: deny by default; server-side enforcement; lock enforcement on both ends (robot side: ADR 0028, P4)
- [ ] V5 Validation: schema validation on all inputs; output encoding by React; no HTML from data
- [ ] V7 Errors and logging: RFC 7807 without internals; security events logged; no secrets in logs; log integrity (CloudWatch, CloudTrail)
- [ ] V8 Data protection: no sensitive data in URLs except single-use WS token; cache-control on API responses `no-store`
- [ ] V9 Communications: TLS 1.2+ everywhere (CloudFront security policy TLSv1.2_2021), HSTS. Default certificate: see R52 and ADR 0046
- [ ] V10 Malicious code: dependencies pinned, audited; actions pinned by SHA
- [ ] V12 Files: upload size/type limits, presigned POST conditions, private bucket, no execution (partial: the presigned POST conditions are in code, ADR 0053, `services/api/src/adapters/s3-site-maps.ts`; the site Lambda IAM is pinned by `infra/envs/demo/tests/site.tftest.hcl`)
- [ ] V13 API: content-type enforced, CORS strict, WebSocket origin check
- [ ] V14 Configuration: security headers, no debug in prod build, source maps not public
